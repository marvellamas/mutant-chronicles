# Lotto 150 — la guardia sulle cartelle vere non dipende da come si lancia (01/11/2026)

Motivo: nel lotto 149 un `node --test` senza `--import` ha scritto `__prova_guardia__.json` in `personaggi/`. La guardia del lotto 145 la caricava soltanto `tests/profilo-di-prova.mjs`, cioè `npm test`: una protezione che si spegne dimenticando una riga di comando.

## A. Dove sta la guardia e come riconosce una prova

`tools/guardia-automatica.mjs` (`riconosciProva`, `attivaGuardiaAutomatica`). Una prova si riconosce **da dentro**, senza che nessuno la dichiari:

1. un test in esecuzione: il test runner di Node mette `NODE_TEST_CONTEXT` in ogni processo che avvia (`node --test`, `npm test`, `node --test file`);
2. `--test` fra gli argomenti di Node o del programma;
3. un file di `tests/` lanciato direttamente (`node tests/x.test.js`);
4. un processo figlio di una prova: la guardia scrive `MUTANT_PROVA=1` nell'ambiente, quindi il server o lo strumento che un test avvia la eredita;
5. un server di prova (porta diversa dalla 3000 o cartelle indicate a mano): come prima, `server.mjs` → `controllaAvvioDiProva`.

Appena una prova è riconosciuta: si calcolano le cartelle vere (le cartelle dei dati dell'app, `PersonaggiBackup/` e la cartella dei dati del profilo di Windows), si installa la guardia di scrittura (errore che nomina il percorso: «Scrittura rifiutata: <percorso> sta nella cartella vera …») e, se manca, si dà al processo un **profilo temporaneo** (`MUTANT_CONFIG_DIR`): nemmeno `%APPDATA%\Mutant` si tocca.

**Dove si accende** (non da chi lancia): la prima riga di ogni file di test (`import '../tools/guardia-subito.mjs'`, 328 file, controllata da un test), `server.mjs`, `tests/profilo-di-prova.mjs` e `cartellaDati` di `tools/dati-pc.mjs` (qualunque strumento che cerca la cartella dei dati, cioè qualunque strumento che può scriverci). **Nessuna variabile la spegne**: ho tolto `MUTANT_GUARDIA_OFF`. `package.json` non carica più nulla con `--import`.

**Il funzionamento normale non cambia**: il server vero sulla 3000 e gli strumenti del menu lanciati da Davide non hanno nessun segno di prova, quindi scrivono come sempre (provato con la stessa sonda in una copia dell'app senza segni: scrive).

### Trovato fuori dalle cartelle dei dati: il profilo di Windows

`%APPDATA%\Mutant\dati.json` (la cartella dei dati scritta nel profilo di questo PC) **punta a una cartella temporanea** (`…\Temp\mutant-datipc-…\utente\Desktop\Mutant\mutant`, «scelta con «Cerca i personaggi»»). Non è un file dei dati di gioco, ma è stato riscritto da una prova: già il 29/10 (il suo backup `dati.json.prima-2026-10-29.zip` punta a un'altra cartella temporanea), il 31/10 alle 08:34 (il mio `node --test` del lotto 149) e oggi alle 10:03. Funzionalmente è innocuo (una cartella dei dati dentro la temporanea si ignora, lotto 138), ma il suo contenuto vero precedente **non si può ricostruire**. L'ho lasciato com'è.

**Chi lo scrive**: non i test di `tests/` (ognuno, lanciato da solo, lascia il profilo identico: provato file per file su tutti), ma i **test della copia non tracciata `distribuzione/mutant/tests`** (297 file): un `node --test` **nudo dalla radice** li trova, li esegue col codice vecchio di quella copia, senza guardia e senza profilo di prova. È la strada che la guardia nel codice di `tools/` non può chiudere. Provvedimenti: `npm test` non la raggiunge; un test (`tests/guardia-automatica.test.js`) avvisa con `ATTENZIONE` (riga diagnostica) quando ci sono file di test non tracciati fuori da `tests/` e **fallisce** se ce n'è uno tracciato; CLAUDE.md dice di non lanciare mai `node --test` nudo dalla radice. Decisione da prendere (non mia): togliere o spostare `distribuzione/mutant/` (è un'altra installazione dentro la copia di lavoro, contro la regola «una sola installazione»).
